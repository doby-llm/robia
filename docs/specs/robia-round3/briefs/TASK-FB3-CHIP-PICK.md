# TASK-FB3-CHIP-PICK — Long-press a "+" chip to choose another tag

## Goal
ui3 F24 (REQ-FB-25, R3-DEC-060). In a review card a tap on a green "+" chip leaves that change out. A long press should offer another tag of the same group (the category or occasion chooser) and replace that chip's tag in place. It changes what a decision writes, so it gets an independent review.

## Steps
1. **Model (pure).** In `ReviewChanges.kt`: `fun ReviewChanges.replaceTag(key: String, newTagId: String): ReviewChanges?` (null when nothing can change). `Add(old)` → `Add(new)` at the same list position (no re-sort); `Swap(from, to)` → `Swap(from, new)` (the `fromLocked` flag is kept); `Remove` (locked or not), an unknown key and `newTagId` equal to the current tag → null. The unit key changes with the tag (`add:<id>`, `swap:<from>:<to>`).
2. **Session (pure).** `TagReviewSession.replaceChip(garmentId: String, key: String, newTagId: String): TagReviewSession` through `updateCard`: refused (card unchanged) unless the card is Pending, `newTagId in card.offeredTagIds`, and `newTagId` is not the tag of another chip of the card (adds and swap `to` halves; the original proposal being replaced is allowed back). On success `changes` is replaced, the old key is removed from `skipped` (picking means on) and `normalized` still applies. The chosen tag of a `needsChoice` card keeps going through `choose` (its "None" clears it). Because `changes` itself is rewritten, `deltaFor`, `primaryButtonFor`, `noTagsLeft`, `bulkPlan`, `commitDeltaFor`, Undo and `AppliedDelta.added` need no change: say in the receipt that you checked each.
3. **Picker options (pure).** In `TagReviewCardModel.kt`: the options for a chip = the card's `offeredTagIds` minus the tags of its other chips (adds and swap `to` halves; the original proposal of the pressed chip stays in); which chips are replaceable (an `Add`, the "+" half of a swap including a swap with a locked `from`, and the chosen tag of a `needsChoice` card; not a `Remove`, not a locked chip, not on a decided card).
4. **Gesture.** In `ReviewChangeChips.kt`, for replaceable chips replace `toggleable` by `combinedClickable(onClick = toggle, onLongClick = ..., onLongClickLabel = ...)`, keeping what TalkBack reads today (`Role.Switch`, the state description) and the light haptic on the tap; add a long-press haptic. `onLongClickLabel` is the new string `review_chip_choose_another` (block `<!-- FB3-CHIP-PICK -->`): EN "Choose another tag", ES "Elegir otra etiqueta", DE "Anderes Tag wählen". Non-replaceable chips keep today's behaviour and have no long-click action. For the swap chip the long press is on the frame (or on the "+" half when `from` is locked). No visible cue is added (Manu removed the hint line).
5. **Picker dialog.** In `TagReviewScreen.kt` the picker target becomes `(garmentId, key)` (key null = the `needsChoice` chooser as today). `TagReviewPickerDialog` gets `showNone` (true only for the `needsChoice` chooser; Add and Swap hide it, because a tap already leaves a change out). Single choice. Selecting a tag calls `replaceChip` (or `choose`). The title is built as today (`tagReviewPickerTitle`, never the garment name). Pass the options from step 3.
6. **Tests.** `ReviewChangesTest`: `replaceTag` cases of V-FB3-CHIP-PICK-1. `TagReviewSessionTest`: V-FB3-CHIP-PICK-2 — skipped migration; each refusal (outside `offeredTagIds`, used by another chip, decided card, locked chip, `Remove`); the delta after a replace; replace → apply → revert restores the original tags; apply → revert → apply writes the replaced tag exactly once; the bulk plan uses the replaced tag; `choose` unchanged. `TagReviewCardModelTest`: V-FB3-CHIP-PICK-3 — picker options, replaceable chips, the new string in three locales.
7. Receipt: the guard list (which check stops each BLOCKING item), the checks of step 2, and the ES/DE strings.

## Tests

## Done when
Rows pass; CI green; the independent review finds no BLOCKING item (write outside the offered group; a tag the garment already has; a double apply after Undo or "Review again"; a bulk plan that still uses the old tag; a replace on a decided card; a "−" or locked chip that changes; a file outside Files; a weakened existing test).

## Do not
Change `deltaFor`, `applyDelta`, `revertDelta`, `primaryButtonFor`, `bulkPlan` or the write path; make a tap open the picker; add a visible hint; offer a tag outside `offeredTagIds`; touch the colour review.
