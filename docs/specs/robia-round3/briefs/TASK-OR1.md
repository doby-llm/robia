# TASK-OR1 — Keep the original photo and the cutout recipe (local)

## Goal
Keep, for every new photo, exactly the frame the engine processed plus the recipe to reproduce the cutout from it (requirements REQ-OR-01/02). Manu found 2048 px too big; the rule "original = engine input frame" means it is never larger than what Robia already works on (1024 precise, ≤ 2048 Standard). This unlocks Keep-mode restore and "Cut out again" for saved garments (OR3), originals in Export (EX1) and backup (OR2).

## Steps
1. `BackgroundRemovalResult` gains `inputFrame: Bitmap? = null` (owned by the caller, recycled after saving) and `recipe: CutoutRecipe? = null`. Precise: the oriented work bitmap before any mask, recipe with `engine="precise"`, crop rect of `cropToAlpha`. ML Kit: the decoded oriented frame (≤ 2048), recipe `engine="mlkit"`, full-frame crop, `sampleSize`. Fallback-to-original: both null.
2. `OriginalPhotoStore.save(context, bitmap): Uri` writes `original-<uuid>.jpg` (JPEG q90) in the same private dir as cutouts.
3. Room v14: `ClothingItemEntity.originalUri` (`original_uri`), `originalRecipe` (`original_recipe`, JSON); `MIGRATION_13_14_SQL` top-level val like v12→13; register it; `ClothingItem.originalUri/originalRecipe`; mappers in `LocalRepositories`.
4. Single add and batch: on save, persist original + recipe; then delete the raw copy and the `subject-*.png` intermediate of that photo (only files under the app's image dir, never the stored cutout or original). Edit of an existing garment that picks a new photo replaces original + recipe and deletes the previous original after the save commits.
5. Commit nothing under `app/schemas` yourself: CI uploads `room-schemas`; state in the receipt that the coordinator must commit `14.json` (as for v13).
